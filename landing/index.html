QualityPilot crawls your app like a user, infers a test plan, and executes it across a browser-and-API execution matrix — security headers, WCAG accessibility, broken links, console and network failures, API contracts, input fuzzing, performance budgets and visual regression. Then it gates your CI with one exit code.

From URL to verified findings

No rules files to write, no test suite to maintain. Point QualityPilot at a URL and it does the four things a QA team does on day one — then keeps doing them on every commit.

Step 1

Crawl

A real browser explores the app: same-origin links, SPA hash routes, forms, API traffic. Redirects that leave the target's origin are refused.

Step 2

Plan

The explorer turns crawled evidence into a validated test plan — pages, flows, API endpoints, fuzz targets, a11y rule scope — every URL SSRF-checked.

Step 3

Execute a matrix

Executors run across browser × viewport × role cells with retry-and-confirm classification, so one-off flakes don't become findings.

Step 4

Gate

Findings are deduped, scored 0–100, and reported as SARIF/JUnit. qualitypilot check exits non-zero when your policy is violated.

What it checks

Ten executors, one engine. Every finding carries evidence, a suggested fix, severity and confidence.

security

Headers, cookies, mixed content

CSP, HSTS, X-Frame-Options, nosniff, Referrer/Permissions-Policy, COOP/CORP, cookie flags, CSP directive weaknesses, credentialed CORS.

accessibility-deep

WCAG 2.x conformance

axe-core over the full A/AA rule universe, mapped to success criteria with a conformance percentage and blockers list.

api-contract

API contract probes

Captured endpoints replayed anonymously: unexpected statuses and schema drift get flagged with the observed response as evidence.

fuzz

Input mutation

Bounded SQLi/XSS/path-traversal/overflow generators against inferred forms and API fields. 4xx responses are accepted — only 5xx and crashes report.

legacy-links / console / network

Runtime health

Broken links (HEAD/GET with retry), JS console errors and exceptions, failed requests — all classified, environmental noise separated.

perf

Performance budgets

CDP metrics (LCP, CLS, TBT) against per-page budgets, under optional network throttling.

visual

Visual regression

Screenshot pixel-diff against baselines with mask selectors; dimension changes are reported, not auto-failed.

e2e

Flow execution

Inferred and authored user flows run in real browsers with selector-timeout evidence and traces on failure.

The CI gate

One command, machine-readable reports, honest exit codes: 0 pass, 1 gate violated, 64 usage, 70 scan failure — a scan that couldn't finish never reports a green pass.

qualitypilot check https://staging.example.com \
  --fail-on critical,high \
  --min-score 80 \
  --max-pages 25 --max-depth 2 \
  --junit junit.xml --sarif sarif.json
$ echo $?
1
FAIL: 2 confirmed finding(s) at severity critical, high

Runs with an explicit --fail-on list count only confirmed findings; a threshold value (e.g. --fail-on high) counts everything at-or-above except environmental failures. Timeouts, DNS and connection failures are classified environmental and never fake a green gate.

Measured, not claimed

Recall is computed against a curated ground truth on OWASP Juice Shop v20.4.0 (local standalone), where every expectation is re-verified against the live target before scoring, and known false-positive modes are asserted must-not-find. Harness and ground truth ship in the repo (benchmark/).

Full surface = the default qualitypilot check pipeline (crawl → inferred plan → 10 executors → dedup → score). Observational detectors (axe, console, links) are reported but excluded from the deterministic denominator by design. The other direction is triaged too: the same pipeline against the official RealWorld Conduit demo produced 0 false positives in 148 findings, each classified against live headers, the served HTML and recorded DOM evidence (benchmark/results/conduit-triage.md).

An agent, not just a CLI

QualityPilot ships an MCP server (qualitypilot-mcp) so coding agents can start scans, read findings, diff runs and export evidence bundles as tools. A dashboard with SSE progress, run diffs and flaky-tracking comes with the repo.
